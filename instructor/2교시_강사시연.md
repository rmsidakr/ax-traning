# 2교시 강사 시연 자료 (강사·보조강사용)

> 강사용 문서입니다. 교안에는 넣지 않습니다. 교안 2교시(3-2. 2교시: 내 업무에 적용해 보기)에는 흐름 그림, 완성 모습(예시 화면 2장과 AI Ready 상자), 2-A~2-D의 과제 설명과 노하우, 모델·Effort 소개(접힘)만 있습니다. 교안은 빔으로만 보여 주고, 교육생은 직접 입력합니다.
> 옛 교안의 접힌 칸 '웹앱이 Gateway를 부르는 방식'은 6절로, '강사 사전 제작 프롬프트 순서'(①~⑤)는 흐름 파일에서 출발하게 고쳐 5절로 옮겼습니다. 옛 '일일 보안 브리핑' 출발점은 버렸습니다.
> **2교시 강사 시연 주제는 '보안정책 불합리 개선 요청' 업무**입니다(접수 → 정책 특정 → 근거·유효성 → 유사 사례 → 차단 이력 → 개선 가능 여부 → 영향도 → 의사결정 회부 메일 보고서 → 결정 적용). 시연 도구는 교안 '완성 모습' 그림과 같은 예시 도구 **'보안정책 개선 검토 도우미'**(`tools/demo_tool`)이고, **실제로 동작할 필요는 없습니다**(2026-10-28 사용자 결정). 값은 가상이고 실제 조회·분석·발송은 하지 않습니다. "이런 개념이다"를 보여 주는 시연입니다(4절 '시연').
> 2교시는 아직 한 번도 돌려 보지 않았습니다. 이 자료의 시각·시간·확인창은 모두 계획(미측정)이고, 리허설(2절·8절)에서 맞춥니다.

## 1. 목표·메시지

- 목표: 1교시 1-D에서 정의한 내 업무 흐름(`prompts\내 업무 흐름.md`)을 브라우저에서 **버튼 하나로** 실행하는 내 도구로 만듭니다. [실행]을 누르면 흐름대로 조회하고 사내 AI가 분석해 미리 보여 주고, 내가 확인한 뒤 [나에게 보내기]로 받습니다.
- 짝: [실행] = ① 조회 + ② 연계·분석, [나에게 보내기] = ③ 받기. 1교시에 말로 한 세 단계가 버튼 두 개가 됩니다.
- 메시지: **"내 업무를 내가 버튼 하나로."** 시작 시연 끝과 2교시 끝에 같은 말로 정리합니다.
- 완성 모습 예시(동작하지 않는 가상 화면)의 목적: 실제로 구현하려면 데이터가 **AI Ready**로 준비돼 있어야 한다는 깨달음. 말할 것은 4절 '시연'·'끝'.
- [실행]할 때마다 흐름 파일 전체를 사내 AI에 넘기므로, 흐름 파일만 고쳐도 분석과 받는 형식이 바뀝니다. 오후 그룹별 실습은 여기서 이어집니다.
- 완료선: 전원 **2-C(받기)까지** 목표, 최소선은 **2-B(미리보기)**, 2-D는 된 사람부터.

## 2. 사전 제작 = 리허설

시연은 예시 도구로 하므로 실제로 동작하는 시연 도구를 따로 만들 필요는 없습니다. 그래도 **강사가 교육 전에 교육생과 같은 방식으로 한 번 만들어 봅니다(리허설).** 그래야 교육생이 보게 될 확인창과 걸리는 시간을 미리 알고, 4절·7절을 맞출 수 있습니다. 리허설 도구는 시연에 쓰지 않습니다.

**만들기 (교육 전, 8절을 재면서)**
- [ ] Windows 교육생 PC(셋팅 노트북을 끝낸 PC)의 실습 폴더 `~\ax-training`에서 Claude Code를 켭니다. 리눅스 개발 PC에서 만들지 않습니다(경로·글자 인코딩·확인창이 다름).
- [ ] 1교시 시연과 같은 흐름(S2 취약점 관리)으로 1-A~1-D를 해서 `prompts\내 업무 흐름.md`를 만듭니다. 교육생과 같은 출발점입니다. 흐름 파일에 부른 조회가 부른 그대로(이름·넣은 값·순서) 남았는지 봅니다. 남아 있어야 2-A에서 다시 찾는 일이 줄어듭니다.
- [ ] 1-D를 한 대화를 이어서(꺼졌으면 `claude -c`) **5절 예시 문장 그대로** 2-A~2-D를 합니다. 시간이 되면 새 대화에서 흐름 파일만으로도 한 번 해 봅니다(대화를 잃은 교육생용). 코드는 직접 고치지 않고, 고칠 것은 교육생처럼 말로 합니다.
- [ ] 분석 모델을 고릅니다. 키로 쓸 수 있는 `internal-*` 모델(사내 데이터를 넣어도 되는 사내 모델) 가운데 [실행]이 한 번에 되는 것 하나입니다. `external-*`은 사외 모델이라 쓰지 않습니다. 교안에는 이름 칸이 없으니 당일 보여 줄 메모를 만들어 둡니다(4절 '2-A').
- [ ] S2가 막히면(앞 조회 결과로 다시 조회하는 KEV·EPSS) 리허설 흐름을 S5(서버·DB 접속 통제, 조회 2번)로 바꾸고, 같은 막힘이 교육생에게 생기면 어떻게 할지 7절에 적습니다.
- [ ] [나에게 보내기]를 실제로 한 번 눌러 도착을 봅니다(8절 3).
- [ ] 리허설 중 확인창 2번('항상 허용')을 눌렀다면 실습 폴더 `.claude\settings.local.json`에서 그 줄을 지웁니다.

**당일 아침**
- [ ] 강사 PC에서 예시 도구를 켜 둡니다: 저장소 맨 위 폴더에서 `python tools/demo_tool/app.py`(기본 포트 8766) → 브라우저 `http://127.0.0.1:8766/`. [실행] → 결과 → '보고서와 사람 확인 2곳을 확인했습니다' 체크 → [나에게 보내기] → 확인 창 → [보내기]('보내기 완료(예시)')가 눌리는지, 빔에서 글자가 읽히는지(브라우저 확대) 봅니다. 켜지 못하면 교안 '완성 모습' 그림으로 같은 순서를 설명합니다.
- [ ] 리허설에서 만든 도구를 더블클릭 파일(2-D)로 켜고 [실행]을 한 번 눌러, 그날 Gateway·모델이 되는지 봅니다(교육생이 막혔을 때 원인을 가르는 기준). 미리보기 캡처를 보조강사에게 나눠 두면, 막힌 교육생에게 "이렇게 나오면 됩니다"로 보여 줄 수 있습니다(빔에 띄우지 않음).
- [ ] 화면 준비는 1교시 2절 '화면'과 같습니다(알림 끄기, 키 파일 열지 않기, 터미널·브라우저 글자 키우기). 브라우저 탭에 다른 사이트를 띄워 두지 않습니다.

## 5. 보조강사용 예시 문장 (2-A~2-D)

교안에는 넣지 않습니다. 막힌 교육생에게 보여 주거나 읽어 줄 때 씁니다. 옛 ①~⑤를 흐름 파일 기준으로 고친 것입니다: ① 계획부터 → 2-A ①, ② 화면만 먼저·③ 조회 연결 → 2-A(처음부터 [실행]과 미리보기만), ⑤ 실행 → 2-A ②와 2-D, ④ 발송 연결 → 2-C. 모두 (미측정)이고, 리허설에서 강사가 이 문장 그대로 해 봅니다.

- **지킬 것은 2-A ①과 2-C 문장 안에 처음부터 넣었습니다.** 나중에 말하면 잘 지켜지지 않습니다. 교육생이 친 문장에 이것이 있는지 봅니다: 내 PC에서만·설치 없이·키 파일은 열어 보지 말고 이름만·키 값은 화면·터미널·오류에 찍지 않기·강사가 정한 `internal-*` 모델만·이름·사번·연락처 빼기 / 받는 사람 고정·미리보기 그대로·한 번 더 확인·보낸 뒤 잠금·보내기는 시험하지 않기. 흐름 파일이 없으면 7절 첫 행.

**2-A ① 계획부터** (줄을 바꾸지 말고 이어 써도 됩니다)
```
방금 1교시에 한 흐름과 prompts\내 업무 흐름.md 를 바탕으로, 이 흐름대로 조회하고 분석하는 일을 브라우저에서 [실행] 버튼 하나로 하는 내 도구를 만들고 싶어. 처음에는 [실행] 버튼과 미리보기만 만들어줘(보내기는 아직 넣지 마).
```

## 6. 도구 구조와 Gateway 부르는 방식 (교육생에게는 보이지 않음)

5절 문장대로 만들면 아래 모양이 되는 것이 목표입니다. 교육생 도구가 막히면 이 표와 견주어 어디가 다른지 봅니다.

| 부분 | 할 일 | 지킬 것 |
|---|---|---|
| 파일 | Python 파일 하나. 표준 라이브러리만(`http.server` + `urllib`) | `127.0.0.1`에서만 엶. 요청의 Host가 `127.0.0.1:포트`가 아니면 거절(강사 비교용, 교육생 문장에는 없음). 흐름 파일은 도구 파일 위치 기준 경로에서 `utf-8-sig`로 읽음(Windows 기본값은 cp949). 인증서 검증을 끄지 않음(`verify=False`, `_create_unverified_context`, `CERT_NONE` 금지) |
| 키 | 실행할 때 코드가 `홈\.claude\litellm-gateway.env`에서 `LITELLM_API_KEY`·`LITELLM_BASE_URL`을 읽음. 값 앞뒤 따옴표·공백은 뗌 | Skill 예제는 환경변수에서 읽어 그대로 쓰면 '키 없음' 오류. Claude Code는 이 파일을 열지 않음. 키 값은 화면·터미널·오류에 찍지 않음(HTTP 오류는 응답 본문만 보임) |
| [실행] ① 조회 | 흐름 파일에 적힌 조회를 만들 때 코드에 넣어 둠(날짜 조건은 오늘 기준). `POST /mcp-rest/tools/call`로 부름 | 실행 때 툴 목록은 찾지 않고 정해진 조회만(`server_id`는 실행 때 찾아도 됨). 이름·인자는 1교시 자료 6절 도구 대응표와 `inputSchema`로 확인 |
| [실행] ② 분석 | 조회 결과와 흐름 파일 전체를 `POST /v1/chat/completions`(강사가 정한 `internal-*` 모델)에 넘김 | 모델 이름이 `internal-`로 시작하지 않으면 멈춤. 넘길 길이에 상한, 잘랐으면 화면에 "전체 N건 중 M건만 분석". 화면에 '분석 중' 표시. 화면·보낼 내용에 이름·사번·연락처 없음. 재시도·timeout은 리허설에서 정함 |
| [나에게 보내기] ③ | `knox_send_messenger` / `knox_send_email`을 부름. 보낼 내용은 방금 본 미리보기 그대로(다시 조회·분석하지 않음) | 받는 사람은 코드에 고정(메일은 `sender`=Knox ID, `recipients`=메일 주소). 미리보기 뒤에만 누를 수 있음. 확인 창에 내 Knox ID(메일이면 주소)가 글자 그대로, 보낼 내용과 함께. 보낸 뒤 버튼 잠금. 인자는 `inputSchema`에서 확인 |

**REST 경로** (인증은 `Authorization: Bearer <Virtual Key>` 헤더 하나. 키는 코드에 쓰지 않고 키 파일에서 읽음)

| 할 일 | 호출 |
|---|---|
| 쓸 수 있는 툴 찾기 | `GET /mcp-rest/tools/list` → 툴 이름·설명·`inputSchema` |
| 서버 이름 → `server_id` | `GET /v1/mcp/server` (리스트를 그대로 돌려줌)에서 `server_name`으로 찾기 |
| 툴 한 번 호출 | `POST /mcp-rest/tools/call`, 본문 `{"name":"<툴>","arguments":{…},"server_id":"<id>"}` |
| 쓸 수 있는 모델 | `GET /v1/models` → `id`가 `internal-*`인 것만 사내 데이터에 씀 |
| 모델 호출 | `POST /v1/chat/completions`, 본문 `{"model":"internal-…","messages":[…]}` → `choices[0].message.content` |

- 툴 응답은 `{"content":[{"type":"text","text":"…"}],"isError":false}` 형태입니다. S2는 `vmanage`·`vulner`, S5는 `lens_secure_vdi_keeper_mcp`·`lens_dbsafer_keeper_mcp`, 받기는 `knox` 서버입니다. 실제 이름과 인자는 반드시 목록에서 확인하고 지어내지 않습니다.
- **Python 표준 라이브러리(`urllib`)로 부릅니다.** 사내 인증서를 OS 신뢰 저장소로 검증해 추가 설정이 필요 없습니다. `requests`·`httpx`는 자체 인증서 묶음을 봐서 `CERTIFICATE_VERIFY_FAILED`가 날 수 있습니다.
- `server_id`를 빼면 `{"error":"missing_parameter"}`, 없는 툴 이름은 404가 아니라 **HTTP 500** + `"Tool … not found"`로 옵니다. 아래 코드는 이 본문을 오류에 보여 줍니다.
- Claude Code에 MCP로 붙일 때 쓰는 `POST /mcp/` + `x-mcp-servers` 방식은 도구에 쓰지 않습니다. 서버 이름에 **오타가 하나라도 있으면 헤더가 무시되고 전 서버의 툴이 열립니다**(차단·격리·발송 툴까지). 도구는 REST로 `server_id`를 지정해 필요한 툴만 부릅니다.

```python
import json, pathlib, urllib.error, urllib.request
env = {}  # 키는 실행할 때 키 파일에서 읽음. 값의 앞뒤 공백·따옴표는 뗌
for line in (pathlib.Path.home() / ".claude" / "litellm-gateway.env").read_text(encoding="utf-8-sig").splitlines():
    if "=" in line and not line.strip().startswith("#"):
        k, v = line.split("=", 1); env[k.strip()] = v.strip().strip("\"'").strip()
B, K = env["LITELLM_BASE_URL"].rstrip("/"), env["LITELLM_API_KEY"]

def gw(path, body=None, timeout=120):                       # 재시도·분석 timeout은 리허설에서(Skill chat 기본 300초)
    req = urllib.request.Request(B + path,
        data=json.dumps(body).encode() if body else None,
        headers={"Authorization": f"Bearer {K}", "Content-Type": "application/json"},
        method="POST" if body else "GET")
    try:
        with urllib.request.urlopen(req, timeout=timeout) as r:
            return json.load(r)
    except urllib.error.HTTPError as e:                      # 응답 본문만 보임. 헤더(키)는 찍지 않음
        raise RuntimeError(f"HTTP {e.code} {path}: {e.read().decode('utf-8', 'replace')[:500]}") from None

sid = next(s["server_id"] for s in gw("/v1/mcp/server") if s["server_name"] == "vmanage")    # ① 조회
data = gw("/mcp-rest/tools/call", {"name": "<툴 이름>", "arguments": {}, "server_id": sid})["content"][0]["text"]
flow = (pathlib.Path(__file__).resolve().parent / "prompts" / "내 업무 흐름.md").read_text(encoding="utf-8-sig")
MODEL = "internal-…"                                         # ② 분석. 강사가 정한 모델
if not MODEL.startswith("internal-"): raise SystemExit("사내 모델(internal-)이 아니라 멈춥니다")
ans = gw("/v1/chat/completions", {"model": MODEL, "messages": [
    {"role": "system", "content": flow}, {"role": "user", "content": data[:20000]}]})          # 상한은 리허설에서. 잘랐으면 화면에 알림
print(ans["choices"][0]["message"]["content"])
```
