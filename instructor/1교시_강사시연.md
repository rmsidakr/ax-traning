# 1교시 강사 시연 자료 (강사·보조강사용)

> 강사용 문서입니다. 교안에는 넣지 않습니다. 교안 1교시에는 단계별(1-A~1-D) 과제 설명과 노하우만 있습니다. 업무별 예시 문장은 이 자료 9절로 옮겼습니다. 교안은 빔으로만 보여 주고, 교육생은 직접 입력합니다.
> 근거는 2026-10-27 리눅스 개발 PC에서 업무마다 1회씩 헤드리스로 돌린 기록입니다. 조회·분석·초안을 한 문장에 넣었고, 아무것도 보내지 않았습니다.
> 헤드리스 실행이라 허용 목록에 없던 명령은 확인창 없이 자동으로 거부됐습니다. 그래서 확인창 수는 실행하려 한 명령 수로 센 추정치이고, '1. Yes'를 누른 뒤의 흐름은 실측과 다를 수 있습니다.
> 세 문장으로 나눈 흐름, 실제 발송, 교육생 PC(Windows)에서의 동작은 모두 (미측정)입니다.

## 1. 시연 목표

교육생이 따라 할 흐름 하나(① 조회 → ② 연계·분석 → ③ 받기)를, 교육생이 보게 될 확인창 그대로 처음부터 끝까지 보여 줍니다.

## 2. 시연 전 준비

**전날**
- [ ] **시연 PC에 등록된 메일 주소 확인.** 10/27에 돌린 리눅스 개발 PC는 등록 주소가 Gateway에 '관제 공용 계정'으로 표시됐습니다(S1 답에서 Claude가 직접 경고). 시연 PC도 같은 주소를 쓰는지 보고, 공용 계정이면 개인 계정으로 바꿉니다. 그대로 두면 받는 주소를 비웠을 때 공용 메일함으로 갈 수 있습니다.
- [ ] **사내 메일과 사내 메신저로 본인에게 1회씩 실제로 보내 봅니다.** 받기 단계는 아직 한 번도 시험하지 않았습니다. 발송 확인창에 도구 이름과 받는 사람이 어떻게 보이는지, 발송 창 앞에 다른 창(메신저 도구 설명 읽기 등)이 더 뜨는지, 도착까지 몇 초 걸리는지 적어 둡니다.
- [ ] **확인창이 교육생과 똑같이 뜨는지 봅니다.** 읽기 명령도 미리 허용하지 않기로 했습니다. 실습 폴더의 `.claude\settings.json`·`.claude\settings.local.json`에 Gateway 명령 허용 줄이 들어 있지 않은지 보고, 리허설 중 2번('항상 허용')을 눌렀다면 그 줄을 지웁니다.
- [ ] 예비 시나리오(S5)도 한 번 돌려 둡니다.

**당일 아침**
- [ ] **시연 시나리오(S2)를 한 번 돌려 값을 봅니다.** KEV·EPSS는 매일 바뀌므로 10/27의 '불일치'와 'D-2'가 그대로 나온다는 보장이 없습니다. 그날 ②에서 찾은 것 1~2개를 메모해 두고, 시연에서는 그것을 짚습니다. ① 표에 이름·사번 같은 사람 정보가 보이지 않는지도 봅니다(빔에 나갑니다).
- [ ] 결과 화면을 캡처해 둡니다. 시연 중에 막히면 캡처로 설명을 이어 갑니다.
- [ ] 아침 시험 메시지는 정리해 둡니다. 그래야 시연 때 새로 온 알림이 눈에 띕니다.

**화면**
- [ ] **프로젝터에 나가도 되는 화면인지** 봅니다. 메일·메신저 팝업 알림을 끄고(③용 메신저 창만 열어 둠), 다른 창을 닫고, 바탕화면 파일 이름을 확인합니다. 휴대폰은 방해 금지 모드로 둡니다.
- [ ] Virtual Key가 든 설정 파일을 열지 않습니다. 터미널 기록에 키가 남아 있지 않은지도 봅니다.
- [ ] 터미널 글자를 키웁니다. 뒷자리에서도 확인창 글자가 읽혀야 합니다.
- [ ] **Claude Code는 교육생과 같은 실습 폴더에서 켭니다.** 폴더 신뢰 창이 뜨면 수락하고, 새 대화로 시작합니다.

## 3. 시연 시나리오 (주): 취약점 관리 (S2)

**입력할 문장 (그대로 붙여넣기)**

① 조회
> 나는 취약점 관리 담당이야. 사내 Gateway에서 최근 한 달 동안 등록된 중요 등급 취약점과 회신 현황, 그리고 거기 나온 CVE가 지금 실제 악용 목록(KEV)에 올라 있는지와 EPSS 점수를 조회해줘.
> 분석에 쓸 건별 내역까지 가져와줘. 사람을 알아볼 수 있는 정보(이름·사번·연락처)는 빼고, 시스템마다 한 번씩만 조회해서 화면에는 건수와 요약 표만 바로 보여줘. 조회만 해.

② 연계·분석
> 좋아. 이 데이터를 CVE 기준으로 엮어서, 많은 데이터 속에서 내 업무에 필요한 것(실제 악용 목록에 올랐는데 회신이 안 된 것과 그게 어디에 몰려 있는지, 우리 기록과 외부 정보가 다른 것)을 찾아 근거와 함께 정리해줘.
> 새로 조회하지 말고 위 데이터만 써줘. 계산은 코드 돌리지 말고 답 안에서 바로 하고, 짐작한 건 짐작이라고 적어줘.

③ 받기 (붙여 넣은 뒤 이어서 강사 본인 Knox ID를 직접 입력하고 Enter)
> 좋아. 이걸 나에게 보낼 사내 메신저 초안으로 만들어줘. 형식: 찾은 것 요약, 5줄 알림. 아직 보내지 말고 초안만 보여줘.
> 도구 이름이나 조회 과정 설명은 빼줘. 받는 사람은 나야. 아래에 Knox ID가 비어 있으면 보내지 말고 물어봐. 내 Knox ID:

초안을 보여 준 뒤에는 "좋아, 보내줘."라고 입력합니다.

- 위 세 문장은 **9절 업무별 예시의 취약점 관리와 글자까지 같습니다.**
- ①의 둘째 줄은 2026-10-28 사용자 결정으로 넓혔습니다. 옛 문장 "요약 숫자만 보면 돼. 명단이나 건별 내역은 보지 말고, …"를 **건별 내역까지 가져오되 사람을 알아볼 수 있는 정보(이름·사번·연락처)는 빼는 것**으로 바꿨습니다. ②에서 많은 데이터 속에서 필요한 것을 찾으려면 건별 데이터가 있어야 합니다. '시스템마다 한 번씩만'과 '조회만 해'는 그대로 두었습니다. '화면에는 건수와 요약 표만'은 답 쓰는 시간을 줄이고 빔에 건별 내역이 길게 나오지 않게 하려고 넣었습니다(미측정).
- 옛 구절은 10/27에 속도를 가른 구절이었습니다(구절이 없으면 124~481초, 세 번 시간 초과). 10/27 실측(113~230초, S2는 136초)은 옛 문장(요약만) 기준이라 새 문장은 더 느릴 수 있습니다. **리허설에서 다시 잽니다**(8절). 10/27에는 ①②③을 한 문장으로 붙여 쟀고, 셋으로 나눈 형태도 (미측정)입니다. ①만 보낼 때는 Claude가 분석 목적을 모르는 채로 조회합니다.
- ②는 새 1-B 정의(많은 데이터에서 내 업무에 필요한 것 분석)에 맞춰 10/28에 고친 문장입니다(미측정). 괄호 안에 업무별로 무엇을 찾을지 적었고, ③의 형식도 '1순위만'에서 '찾은 것 요약'으로 바꿨습니다. S2는 ①의 범위도 '10건'에서 '최근 한 달'로 넓혔습니다.
- ②의 "짐작한 건 짐작이라고", ③의 "초안만 보여줘"·"조회 과정 설명은 빼줘"·(메일 예시의) "확인창 맨 앞에"·끝의 "내 Knox ID:"는 예시 문장에 맞춰 덧붙인 구절입니다(미측정).
- ③은 처음부터 **초안만** 받습니다. 받는 사람(내 Knox ID)은 문장 끝에 직접 입력합니다. 붙여 넣은 글이 길면 Claude Code 입력창에서 `[Pasted text …]`로 접혀 가운데를 고칠 수 없기 때문입니다.

**뜨는 확인창과 읽을 것** (①은 10/27 한 문장 실행에서 실행하려 한 명령 7개 기준으로 약 7개. ②·③은 미측정)

| 단계 | 창에 보이는 것 | 뜻 | 누를 것 |
|---|---|---|---|
| ① | Skill `litellm-gateway` | 사내 Gateway 안내 불러오기 | 1. Yes |
| ① | `litellm_gw.py search …` | 맞는 데이터 찾기 | 1. Yes |
| ① | `litellm_gw.py tools --server …` | 도구 설명 읽기 (10/27에는 vmanage·vulner 두 서버를 한 창에 이어 붙여 읽음) | 1. Yes |
| ① | `litellm_gw.py memory list` | 부서 메모리 읽기 | 1. Yes (10/27에는 거부된 채 진행됨. Yes 뒤 흐름은 미측정) |
| ① | `call-tool vmanage vmanage_list_vulnerabilities`, `call-tool vulner vulner_check_kev`, `call-tool vulner vulner_check_epss` (창 3개) | 사내 기록 조회, 외부 KEV·EPSS 조회 | 1. Yes |
| ② | (미측정) 거의 없을 것으로 봄. 코드가 길게 든 창이면 계산하려는 것 | 계산 시도 | 3. No → "계산은 답에서 바로 해줘" |

| ③ | (미측정) `call-tool knox knox_send_messenger …` | 메신저 보내기 | 받는 사람이 나이고 내용이 초안이면 1. Yes |

- 첫 창 한두 개는 천천히 소리 내어 읽습니다. "`litellm_gw.py` 다음 단어를 봅니다. search·tools·servers는 찾기입니다. call-tool은 실제로 부르는 것이라, 바로 뒤의 서버·도구 이름까지 읽습니다. 이름에 send·create·update·delete·set이 있거나 처음 보는 도구면 멈춥니다."
- 시연 ①에서 call-tool 뒤에 나와야 할 도구는 위 표의 세 개뿐입니다. 다른 이름이 나오면 3번 No를 누르고, 왜 멈췄는지 보여 주는 장면으로 씁니다.
- ③ 창에서는 받는 사람이 내가 적은 내 계정 하나뿐인지, 내용이 방금 본 초안과 같은지 읽어 줍니다. 받는 사람을 찾으려고 인명 조회(`knox_get_employee_info` 등) 창이 뜨면 3번 No를 누릅니다. 계정은 이미 직접 적었습니다(미측정). 2번('항상 허용')은 누르지 않는다고 한 번 더 말합니다.

**걸리는 시간**
- 10/27 한 문장 실측은 136초였습니다(옛 문장, 요약만 조회. 조회 3회, 1회 약 0.75달러). 확인창을 누르는 시간은 빠진 값입니다.
- 세 문장 흐름은 (미측정)입니다. ① 1~2분, ② 1~2분, ③ 초안 30초~1분에 발송까지로 잡아 둡니다(요약만일 때의 추정). 건별까지 가져오는 지금 ①은 조회 크기가 커서, ②는 읽을 데이터가 많아서 더 걸릴 수 있습니다. 확인창 7개를 소리 내어 읽으면 ①은 더 걸립니다.
- 10/27 S2 로그로 보면 찾기와 조회 3회가 처음 약 40초 안에 끝났고(조회 1회는 0.5~1.7초), 나머지 약 90초가 엮어서 쓰는 시간이었습니다. 6개 업무 전체로는 찾기 약 20~50초(S1만 약 100초), 엮어서 쓰기 약 80~190초였습니다.

**기다리는 동안 할 말**
- ① 찾는 중: "도구 이름은 하나도 알려 주지 않았습니다. Claude가 사내 Gateway에서 맞는 데이터를 스스로 찾는 중입니다."
- ① 답을 기다릴 때: "분석에 쓸 건별 데이터까지 가져오라고 했습니다. 이름·사번 같은 사람 정보는 빼 달라고 했습니다. 지금은 가져온 데이터를 정리해 쓰는 시간입니다."
- ②: "이 단계는 Gateway에 다시 가지 않습니다. ①에서 가져온 많은 데이터 속에서 LLM이 내 업무에 필요한 것을 찾습니다. 사람이 하나씩 보기 어려운 양을 한 번에 엮어 보는 일입니다. 그래서 확인창이 거의 없습니다." (미측정. 다시 조회하는 창이 뜨면 3번 No를 누르고 "새로 조회하지 말고 위 데이터만 써줘"라고 입력합니다.)
- ③ 초안: "보내기 전에 먼저 보여 달라고 했습니다. 내가 확인해야만 나에게 옵니다."

**짚어 줄 '찾은 것'** (10/27 예시입니다. 옛 문장(최근 10건, 요약만)으로 얻은 값이고, 매일 바뀌므로 아침에 메모한 것을 짚습니다.)
- 우리 기록과 외부 정보의 불일치: KEV 등재 여부가 3건 달랐고, 3건 모두 '사내 기록은 미등재, 외부는 등재'였습니다. 그중 PAN-OS·F5 2건은 10/26에 새로 등재된 것이었습니다. EPSS는 4건이 실제보다 낮게 적혀 있었고 1건은 비어 있었습니다.
- 조치기한 임박: PAN-OS·F5 건의 CISA 조치기한이 10/29(D-2)였고, EPSS는 약 1.0이었습니다.
- 실제 악용 목록에 올랐는데 회신 안 된 곳: PAN-OS·F5 두 건에서 10곳(6곳 + 4곳)이 회신하지 않았습니다(10/27 답은 이것을 독촉 1순위로 꼽음). 조치기한이 이미 지난 건은 독촉을 5번 하고도 1곳이 남아 있어, Claude가 윗선 보고를 제안했습니다.
- 찾은 것 하나를 골라 그 근거(CVE·건수)를 ①에서 가져온 데이터에서 찾아 보여 줍니다. ①의 요약 표에 없으면 "이건 위 데이터 어디에 있었어?"라고 묻습니다. "지어낸 것이 아닌지 이렇게 확인합니다."
- 답에 Claude가 근거로 쓴 조회 이름을 밝힐 수 있습니다(10/27에는 6개 업무 모두). Skill이 근거를 밝히도록 돼 있어서 그렇다고 설명합니다.
- 10/27 초안 예시 (보내지 않음, 옛 형식 '1순위만'. 원문 5줄 중 4줄, 일부 줄임. 지금 ③은 '찾은 것 요약'이라 첫 줄 모양이 달라집니다):
```
[독촉 1순위] PAN-OS·F5 취약점
- 10/26 KEV 신규 등재, CISA 조치기한 10/29(D-2)
- 미회신 10곳 (PAN-OS 6/24, F5 4/24)
- 사내 기록 KEV '미등재' 상태 → 표시 수정 필요
```

## 4. 예비 시나리오: 서버·DB 접속 통제 (S5)

- 가장 빨랐습니다. 한 문장 실측 113초(옛 문장, 요약만 조회), 조회 2회, 확인창 약 5개, 거부된 명령 0개, 1회 약 0.65달러.
- **바꾸는 때**
