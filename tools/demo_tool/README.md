# 보안정책 개선 검토 도우미 (예시 화면 · 가상 값)

교안 2교시 '완성 모습' 화면과 **2교시 강사 시연**에 쓰는 예시 도구입니다. 실제로 조회·분석·발송하지 않습니다("이런 개념이다"를 보여 주는 용도).
'보안정책 불합리 개선 요청' 업무 10단계를 `prompts\내 업무 흐름.md` 하나로 [실행]하면
① 조회 → ② 사내 AI 분석 → ③ 받을 보고서 초안까지 가로로 보여 주고, 미리보기를 확인한 뒤에만 [나에게 보내기]를 누를 수 있게 한 모습입니다.

**이 화면이 전하려는 것:** 이렇게 [실행] 한 번에 1~8단계가 돌려면 도구가 쓰는 데이터가 **AI Ready**(AI가 읽을 수 있게 정리된 상태)로 준비돼 있어야 합니다. 준비가 덜 된 데이터에서 나온 결과는 AI가 짐작한 것이므로 '짐작 · 사람 확인'으로 표시하고, 보고서에도 '사람 확인'으로 넣어 보내기 전에 내가 확인합니다.

| 업무 10단계 | 화면에서 |
|---|---|
| 1 요청 접수 | ① 조회: 접수된 요청 (개선 요청 접수함) |
| 2 개선할 정책 특정 | ② 분석: 요구사항 → 매칭 정책 |
| 3 현행 정책 근거 확인 | ① 정책문서·KM 조회 + ② 판정 |
| 4 현행 정책 유효성 확인 | ② 판정 |
| 5 유사 사례 확인 | ① KM 조회(승인 1·반려 1) + ② 판정 |
| 6 개선 필요성 확인 | ① Splunk 차단 이력(일별 추이) + ② 판정 |
| 7 개선 가능 여부 판단 | ② 판정 (KM이 일부만 준비돼 '△ 사람 확인') |
| 8 영향도 분석 | ② 충돌 정책(정책 간 관계 데이터가 없어 '✗ 짐작 · 사람 확인')·바꿀 설정 규모·영향 사용자 |
| 9 의사결정 회부 | ③ 메일 보고서 초안(‘사람 확인’ 2곳 포함) → **나에게**(받는 사람 `나 · ax.user01 · ax.user01@example.com` 고정). 결재권자 전달은 내가 직접 |
| 10 결정사항 적용 | ④ 다음 단계로 표시만 (결정 메일 분석 → KM 히스토리·요청자 회신 초안, 적재·회신은 사람이 확인한 뒤) |

## 데이터 AI Ready 상태 띠

단계 표시 바로 아래 띠에 이 도구가 쓰는 데이터 출처 5곳의 준비 상태를 보여 줍니다. 값은 `app.py`의 `readiness`·`readiness_note`에 있습니다.
띠 문장은 "이 화면이 되려면 데이터가 AI가 읽을 수 있게 준비돼 있어야 합니다. △·✗인 곳은 AI가 짐작하므로 사람이 확인합니다."입니다.
교안에서 0.82배(본문 폭 약 1316px)로 줄어도 띠 글자가 14px 넘게 보이도록 띠만 크게 썼습니다(제목 22px, 문장 18px, 출처 이름 20px, 상태·이유 18px). 이유는 칸 안에 한 줄로 들어가게 짧게 적었습니다.

| 출처 | 상태 | 이유 | 화면에서 이어지는 곳 |
|---|---|---|---|
| 개선 요청 접수함 | ✓ 준비됨 | 요청이 항목별로 나뉨 | ① 접수된 요청 |
| 정책문서 | ✓ 준비됨 | 조항 번호(§4.2)로 찾음 | ① 매칭 정책 · ② 근거 확인 |
| KM 결정 이력·유사 사례 | △ 일부 | 결정은 항목, 옛 사례는 본문에만 | ① 유사 사례 · ② 7단계 '△ 사람 확인' · ③ 보고서 '옛 유사 사례' |
| Splunk 차단 이력 | ✓ 준비됨 | 부서·서버·날짜로 바로 셈 | ① 차단 이력 · ② 개선 필요성 |
| 정책 간 관계 | ✗ 안 됨 | 연결 정보 없음 → AI가 짐작 | ② 2·8단계 '✗ 짐작' · ③ 보고서 '정책 충돌 여부' |

같은 ✓/△/✗ 기호가 띠, ① 출처 칩, ② 짐작 표시, ③ 보고서의 '사람 확인' 줄, 확인 창에 똑같이 쓰여 데이터 준비 상태 → 결과의 확실성 → 사람이 확인할 곳이 한 줄로 이어집니다. 보내기 앞 체크도 '보고서와 “사람 확인” 2곳을 확인했습니다'입니다.

## 화면 구성

화면 위쪽 진행 표시에 10단계가 그대로 보이고, [실행] 한 번에 도는 1~8단계(①+②), ③ 받기(9), ④ 결정 적용(10)이 묶여 보입니다. 단계 밑의 ①②는 그 단계가 조회와 분석 중 무엇을 쓰는지 표시합니다.

- **실제로 조회·분석·발송하지 않습니다.** 결과는 `app.py` 안의 가상 값(`DEMO_RESULT`)이고, 보내기는 가짜 성공만 돌려줍니다.
- 요청 번호(`REQ-2610-018`), 정책 번호(`POL-NET-031` 꼴), KM 문서 번호(`KM-0412` 꼴), 부서(A팀~D팀), 도메인(`example.com`), IP(`192.0.2.x`), 받는 사람의 Knox ID(`ax.user01`)와 메일 주소(`ax.user01@example.com`)는 모두 지어낸 값입니다. 실제 사람 이름·사번·연락처·사내 호스트는 넣지 않았습니다.
- 받는 사람은 미리보기(③)·확인 창·보낸 뒤 창에 `나 · ax.user01 · ax.user01@example.com`으로 글자 그대로 보이고, 바꿀 수 없게 고정입니다. 값은 `app.py`의 `draft.to`·`to_knox`·`to_mail`입니다.
- Python 표준 라이브러리만 씁니다. `127.0.0.1`에서만 열리고, 외부 네트워크와 키 파일은 쓰지 않습니다.
- `index.html`은 외부 리소스 없는 한 파일입니다(글꼴: Malgun Gothic → Noto Sans CJK KR).

| 파일 | 내용 |
|---|---|
| `app.py` | `/` → index.html, `/api/run` → 가상 결과 JSON, `/api/send` → 가짜 성공 |
| `index.html` | 도구 화면. [실행] → 10단계 진행 표시와 ①②③을 차례로 채움, 체크 후 [나에게 보내기] → 확인 창 |

## 실행

```
python tools/demo_tool/app.py --port 8766   # 저장소 맨 위 폴더에서. 리눅스는 python3
```

브라우저에서 `http://127.0.0.1:8766/` 를 엽니다. 끄기는 Ctrl+C.

## 캡처

결과가 다 나온 화면과 확인 창을 바로 띄우는 주소가 있습니다.

- `http://127.0.0.1:8766/?state=done` : [실행]이 끝난 화면(미리보기 확인 체크까지 된 상태)
- `http://127.0.0.1:8766/?state=confirm` : 위 화면에 [나에게 보내기] 확인 창을 띄운 상태

화면 크기 1600×1000(배율 1)에서 스크롤 없이 한 화면에 들어가게 맞췄고, 화면의 글자는 모두 14px 이상입니다.
`?state=confirm` 화면에서 확인 창(흰 창)만 잘라 쓸 때의 화면 좌표는 (x0, y0, x1, y1) = (470, 221, 1130, 779)입니다(660×558, 테두리 포함, 끝 좌표는 미포함).

- 손으로 찍기: Chrome·Edge에서 위 주소를 열고 F12 → 기기 모드(Ctrl+Shift+M) → 크기 1600×1000, 배율 100% → 점 3개 메뉴의 '스크린샷 캡처'.
- 자동으로 찍기: 헤드리스 Chrome을 CDP로 열어 `Emulation.setDeviceMetricsOverride`(1600×1000, 배율 1)를 주고, `body[data-ready="1"]`이 될 때까지 기다린 뒤 `Page.captureScreenshot`으로 찍습니다.
- `google-chrome --headless --window-size=1600,1000 --screenshot=…`은 보이는 영역이 창보다 작게 잡혀 아래쪽이 잘립니다. 쓰지 않습니다.
